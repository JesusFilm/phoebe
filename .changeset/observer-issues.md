New catalog kind `observer` (`path: "phoebe-agent/kinds/observer"`), declared in a pipeline of its own. With `every` set, it runs once per `every` after its last completed run. It reads that run from its own unit history on disk, so a restart does not cause an extra run. Each run reads the unit history of every other pipeline in the tenant over `lookback` (14 days by default) and flags units that failed, timed out, were abandoned or were quarantined. One read-only agent run groups the flagged units into findings. Each finding has a category (`ticket`, `convention`, `factory` or `engine`) and a target. The kind files each finding as an issue labelled `phoebe:observer`, never the ready label, with the marker `<!-- phoebe-observer finding=<category>:<target> -->`. When an issue with the same key is open, the kind comments on it with the units the issue does not list yet. A key whose last issue was closed as not planned, or closed any other way short of completed, in the last 90 days is skipped. A key whose last issue was completed is filed again as a regression. A run files at most `maxProposals` new issues (3 by default). `mode` takes only `"issues"` for now, and `"pr"` fails registration. A kind's `run` may now resolve with `{ summary }`, and the engine stores that line as the `detail` of the unit's record. The observer's summary looks like `2 proposals filed (#41, #42), 1 folded into #38, 1 skipped; coverage work 14d, intake 9d`.
