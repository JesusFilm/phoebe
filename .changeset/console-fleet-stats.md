The console has a stats button beside the settings gear at the foot of the rail. It is the gear's size and shows a chart icon. Rest the pointer on it for half a second and a card opens with totals across every deployment the console knows: API spend, the subscription estimate, units, and units that did not complete, over the last 24 hours or 7 days, with one line per deployment. The card stays open while the pointer moves onto it and closes 300 ms after the pointer leaves both. Clicking the button opens the fleet stats page at `#/stats`. The page has tiles for the same four figures, a chart of units per day, tables by deployment and by model, and the five most expensive units. Each of those units opens the History tab's drawer. Choosing an install on the rail leaves the page. The totals come from each deployment's report summary. A deployment whose report has no summary is listed as too old and left out of the totals rather than counted as zero. A folder that is also paired counts once. The units per day, the model table and the most expensive units come from each deployment's history, read when the page opens, up to 1,000 units per deployment. API spend and the subscription estimate are shown side by side and never added together.
