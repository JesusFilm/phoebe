The `observer` kind gains PR mode, and `mode: "pr"` is now the default. A `convention` or `factory` finding gets one agent run that edits a fresh worktree of the default branch. Code then checks every path the edit changed. An observer PR may change `AGENTS.md`, `prompts/**`, `phoebe.config.ts`, and files inside skill directories under `.agents/skills/` that `skills-lock.json` does not list. When every path passes, the kind commits the edit, pushes it to `<branchPrefix>observer/…`, and opens a PR labelled `phoebe:observer` with the finding marker. Any other path, a vendored skill included, turns the proposal into an issue that names the paths, and nothing is pushed. A fix to a prompt or config that the repository does not track at that path becomes an issue carrying the suggested diff. When those files are missing from the repository, the kind first copies the live ones from the runtime root into the worktree, so the diff applies where they live. `ticket` and `engine` findings stay issues. Dedupe now reads PR proposals too: a merged PR counts as completed, and one closed unmerged counts as turned down. `mode: "issues"` keeps the old behaviour. The GitHub client gains `createPullRequest`, which returns the new PR's number, and `listPrsMentioning` hits now carry `closedAt`.
