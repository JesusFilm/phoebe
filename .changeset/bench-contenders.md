`phoebe bench run` now compares named contenders. Pass `--bench-config <file>` with a JSON file that lists contenders by name. Each contender can set `provider`, `model`, `effort` and `promptFile`, and the tenant's `issues` settings fill in whatever it leaves out. A `promptFile` can be anywhere in the deployment directory, so you can try a prompt before installing it. `repeat` (default 1) replays each fixture and contender pair that many times, and `--concurrency` (default 1) runs that many trials at once. When the run ends, bench prints one row per contender: trials, no-change count, check and test pass rates, median duration and tokens, and API cost and subscription estimate in separate columns, with a dash where the provider reported nothing. `--json` prints the `BenchReport` (`v: 1`, exported from `phoebe-agent/contracts`) instead, and `report.json` holds the same JSON. `phoebe bench report <runId>` prints a saved run's report again. The exit code is 0 whenever every trial ran, whatever the scores. A bad suite or bench config, a missing prompt file, or a contender whose provider key is unset stops the run before any trial starts.
